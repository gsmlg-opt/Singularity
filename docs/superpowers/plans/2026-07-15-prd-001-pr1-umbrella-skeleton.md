# Singularity PR 1 Umbrella Skeleton and Contracts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build PRD-001's first delivery slice: a five-application Mix umbrella with mechanically enforced dependency boundaries, typed domain and adapter contracts, deterministic test fakes, reusable contract suites, reproducible tooling, and CI.

**Architecture:** `singularity_core` owns pure domain values and behaviours; `singularity_store` and `singularity_retrieval` depend only on core; `singularity_runtime` composes those capabilities; `singularity_web` depends only on runtime. PR 1 uses plain library applications and standard Elixir/OTP only. Supervisors, Phoenix, CouchDB, Qdrant, Backplane HTTP, workflow functions, and model calls remain in their later PRD delivery slices.

**Tech Stack:** Elixir `~> 1.18` (CI 1.18.4), Erlang/OTP 28, Mix umbrella, ExUnit, Agent-backed test fakes, devenv pinned to nixpkgs `release-26.05`, GitHub Actions.

---

## Scope guard

This plan implements only PRD-001 §17 “PR 1 — Umbrella skeleton and contracts.” Stop when the PR 1 checklist passes.

Do not add:

- Phoenix, LiveView, Ecto, or web routes;
- CouchDB, Qdrant, Req, Backplane, or Synapsis dependencies;
- normalization, parsing, chunking, embedding, retrieval, RAG, or export workflows;
- placeholder public functions returning `:not_implemented`;
- Oban, GenServers, supervisors, registries, ETS tables, or other runtime processes outside the stateful test fakes;
- an ID-generation algorithm, provider-specific response map, or CouchDB `_id`/`_rev` field in a domain struct.

If a later implementation step exposes a missing feature or bug in a dependency from an organization listed in the repository instructions, follow the upstream issue-routing policy. PR 1 intentionally has no such runtime dependency, so an upstream issue should be exceptional.

## Decisions fixed for PR 1

1. Use the organization’s committed compatibility baseline: `elixir: "~> 1.18"`, CI Elixir `1.18.4`, and OTP `28`. Treat an upgrade to Elixir 1.20/OTP 29 as a separate toolchain change.
2. Generate all five children without `--sup`. Add an Application callback only in the later PR that introduces a real supervised responsibility.
3. Generate `singularity_web` as a plain Mix child. Add Phoenix with `mix phx.new.web --no-ecto` during PR 6, when endpoint, router, PubSub, assets, and authentication decisions belong in scope.
4. Keep all PR 1 runtime dependencies inside the umbrella. Test support uses Elixir/OTP and ExUnit only.
5. Represent domain IDs, hashes, model identifiers, pipeline versions, and opaque concurrency tokens as strings. Represent times as UTC `DateTime` values and metadata as maps with string keys.
6. Set the initial schema version to `1`. Reject non-positive values and positive versions other than `1`.
7. Keep CouchDB metadata outside domain structs. `Singularity.Core.Stored` carries a domain value and opaque `version` token for optimistic replacement.
8. Every behaviour callback receives an explicit adapter context as its first argument. Production contexts will hold client configuration; PR 1 fakes receive an isolated PID.
9. Model generation streaming as a synchronous callback sink: the generator sends ordered `GenerationEvent` values to a one-argument function and then returns a `GenerationResult`.
10. Enforce the declared Mix dependency graph with both an exact allow-list test and `mix xref graph --format cycles --fail-above 0`.

defmodule Singularity.Architecture.DependencyGraphTest do
  use ExUnit.Case, async: false

  @repo_root Path.expand("../../../../..", __DIR__)

  @expected_dependencies %{
    singularity_core: [],
    singularity_store: [:singularity_core],
    singularity_retrieval: [:singularity_core],
    singularity_runtime: [
      :singularity_core,
      :singularity_store,
      :singularity_retrieval
    ],
    singularity_web: [:singularity_runtime]
  }

  test "child projects declare exactly the required internal dependency graph" do
    expected_apps = Map.keys(@expected_dependencies)
    actual_apps = child_apps()

    assert MapSet.new(expected_apps) == MapSet.new(actual_apps)

    actual_dependencies =
      Map.new(actual_apps, fn app ->
        {app, declared_dependencies(app)}
      end)

    assert @expected_dependencies == actual_dependencies
  end

  test "all child projects use the centralized Elixir requirement" do
    expected = Singularity.Build.elixir_requirement()

    for app <- child_apps() do
      assert expected == project_config(app)[:elixir]
    end
  end

  defp child_apps do
    @repo_root
    |> Path.join("apps/*/mix.exs")
    |> Path.wildcard()
    |> Enum.map(&(&1 |> Path.dirname() |> Path.basename() |> String.to_existing_atom()))
  end

  defp declared_dependencies(app) do
    app
    |> project_config()
    |> Keyword.fetch!(:deps)
    |> Enum.map(fn
      {dependency, [in_umbrella: true]} -> dependency
      unexpected -> flunk("unexpected dependency declaration: #{inspect(unexpected)}")
    end)
  end

  defp project_config(app) do
    path = Path.join(@repo_root, "apps/#{app}")

    Mix.Project.in_project(app, path, fn _module ->
      Mix.Project.config()
    end)
  end
end
```

defmodule Singularity.Core.Types do
  @moduledoc "Shared primitive domain types."

  @type id :: String.t()
  @type hash :: String.t()
  @type version :: String.t()
  @type timestamp :: DateTime.t()
  @type metadata :: %{optional(String.t()) => term()}
end

defmodule Singularity.Core.Error do
  @moduledoc "Stable errors returned across adapter boundaries."

  @enforce_keys [:code]
  defstruct [:code, :message, details: %{}, retryable?: false]

  @type code ::
          :not_found
          | :already_exists
          | :conflict
          | :invalid
          | :unsupported
          | :unavailable
          | :timeout

  @type t :: %__MODULE__{
          code: code(),
          message: String.t() | nil,
          details: map(),
          retryable?: boolean()
        }
end

defmodule Singularity.Core.SchemaVersion do
  @moduledoc "Validates PRD-001 canonical schema versions."

  alias Singularity.Core.Error

  @current 1

  def current, do: @current
  def validate(@current), do: :ok

  def validate(version) when is_integer(version) and version > 0 do
    {:error, %Error{code: :unsupported, details: %{schema_version: version}}}
  end

  def validate(version) do
    {:error, %Error{code: :invalid, details: %{schema_version: version}}}
  end
end

defmodule Singularity.Core.Stored do
  @moduledoc "A domain value paired with an opaque persistence version."

  @enforce_keys [:value, :version]
  defstruct [:value, :version]

  @type t(value) :: %__MODULE__{value: value, version: String.t()}
end
```

## Task 6: Add deterministic stateful fakes and reusable contract suites

**Files:** All core `test/support/fake`, `test/support/contracts`, and fake contract test files from the file map.

- [ ] **Step 1: Add one process-isolated control API**

`Singularity.Core.TestSupport.Fake.Control` owns an Agent with this state:

```elixir
%{
  data: initial_data,
  calls: [],
  next_error: nil
}
```

Its public API is exactly:

```elixir
start_link(initial_data)
calls(pid)
fail_next(pid, %Singularity.Core.Error{})
run(pid, callback_name, arguments, state_function)
```

`run/4` appends `{callback_name, arguments}` to `calls`. If `next_error` is set, it clears that field and returns `{:error, error}` without calling `state_function`. Otherwise it calls `state_function.(data)` and requires `{result, new_data}`.

- [ ] **Step 2: Write the KnowledgeStore contract before its fake**

Each reusable contract is an `__using__/1` macro that requires:

```elixir
use ContractModule,
  adapter: FakeModule,
  start_context: {FakeModule, :start_link, [[]]}
```

The contract calls the supplied MFA in `setup`, pattern-matches `{:ok, context}`, and registers `on_exit(fn -> if Process.alive?(context), do: Agent.stop(context) end)`. It must define tests for:

1. creating/fetching an item returns `%Stored{version: "1"}`;
2. replacing with the current version increments it to `"2"`;
3. replacing with a stale version returns `%Error{code: :conflict}`;
4. both item creation and replacement reject every head referencing a missing revision with `%Error{code: :invalid}`;

6. reusing a revision ID for different content returns `%Error{code: :already_exists}`;

8. retrying an identical chunk is idempotent, while reusing a chunk ID for different content returns `%Error{code: :already_exists}`;
9. projection state is replaceable because it is recoverable operational state;
10. answer runs are terminal append-only records and duplicate IDs return `:already_exists`;
11. `fail_next/2` affects one call and records the attempted call.
